User reports that built-in brush presets make general Preview unusable in dd.mb. Separate owned Maya2025 PID59504/private preferences opened a copy; user Maya PID8220 and original scene untouched. Disk scene has170 render meshes (~74k triangles) and two line sets. Test applies each built-in brush to both sets at saved widths1.0/1.2px, with original feature settings including intersections. This is an all-lines stress case; unsaved user edits may differ.

Root cause: opt-in procedural brush coverage expands every mesh/intersection candidate into5–9 thin jittered paths. Any camera movement redoes screen-space phase, subdivisions, noise, projection and metadata. Ordinary133236 candidate segments become about3.11 million for Rough Ink. Scalar Python per-edge expansion repeatedly allocates arrays and computes identical transforms; domains also rounded each endpoint separately on every refresh.

Changed only the retained general Preview path: vectorized procedural coverage in bounded64-edge batches, indexed metadata gathering, one basis inverse per batch, and bounded32MiB/256-entry world-connectivity cache. Screen lengths and orientation still evaluated at the current camera, and geometry edits invalidate connectivity by rounded world coordinates. No sample interval, lane count, thresholds or rendered CPU algorithm was reduced. Mixed ordinary/PNG/brush submissions retain order and pressure/facing metadata. Existing PNG expansion is not optimized by this change.
