# ReaPencil 0.8.17 — CPU 첫 렌더와 메시 변형 최적화 (로컬 검증본)

Maya 2025 실제 렌더러를 별도 프로세스에서 실행했습니다. 말·마차 전체 장면의 스무스 적용 형상 2,634,968개 삼각형, 1920×1080, 2배 샘플링, 동일 카메라/프레임으로 비교했습니다. Ryzen 9 7900X, Windows x64입니다.

새 Maya 프로세스 3회 측정의 중앙값입니다. 형상 평가·추출, CPU 렌더, PNG 저장을 포함합니다. 장면 열기, 렌더 명령 전의 플러그인 로드, Render View 표시는 제외했습니다. CPU 준비 작업을 렌더 타이머 밖으로 옮기지 않았습니다.

| 상황 | ReaPencil 0.8.17 | Pencil+ | 시간 감소 |
|---|---:|---:|---:|
| 프로세스 최초 렌더 | 2.19초 | 2.40초 | 8.7% |
| 같은 프레임 반복 | 1.02초 | 2.25초 | 54.6% |
| 가장 큰 메시의 전체 정점 변형 | 1.25초 | 2.27초 | 44.9% |
| 장면 전체 메시의 전체 정점 변형 | 2.13초 | 2.26초 | 5.8% |

큰 메시 검증은 rope_6의 원본 정점 14,706개 전체를 곡선 형태로 변형했습니다. 전체 변형은 104개 메시, 원본 정점 85,112개를 변형했습니다. 동일한 변형을 양쪽 렌더러에 적용했습니다. 원본 장면 파일은 변경하지 않았습니다. 이 장면과 측정 환경에서의 결과이며 모든 장면의 우위를 보장하지 않습니다.

기존 로컬 0.8.16은 같은 변경 시나리오에서 최초 5.57초, 큰 메시 변형 2.90초, 전체 변형 4.65초였습니다(각 1회). 최적화 전후의 모든 검증 PNG가 알파를 포함해 바이트 단위로 일치했습니다. Pencil+와 ReaPencil 사이의 기존 표현 차이를 없앤 변경은 아닙니다.

변경 사항:

- 삼각형 준비, BVH 생성, 정밀 교차 판정, 깊이·가림 판정, 선 합성, 축소 필터를 별도 C++ CPU 라이브러리로 구현했습니다. GPU를 사용하지 않습니다.
- BVH는 반복 전체 정렬 대신 결정적인 중앙값 분할을 사용합니다. 기존 안정 정렬과 같은 삼각형·노드 순서를 유지하도록 동률 기준을 보존합니다.
- Maya 형상 추출 중 CPU 깊이/외곽선/BVH 준비를 동시에 수행합니다. Maya API 호출은 메인 스레드에 남겼습니다.
- 선 합성은 서로 겹치지 않는 행 구간으로 나눠 계산합니다. 각 픽셀의 선 순서, float32 알파 합성, 가림 판정과 선 기록 순서를 유지합니다.
- 메시 전달에 프로세스 내 메모리를 사용해 임시 파일 쓰기/읽기를 없앴습니다. 스무스 형상은 동일한 Maya 평가 방식으로 계산합니다.
- 모든 면의 재질 및 라인셋이 같은 경우에만 불필요한 면 출처 계산을 생략합니다. 부분 면, 혼합 재질, 선택 엣지, 알파 경계에서는 필요한 출처 정보를 유지합니다.
- 캐시 메모리의 반복 전수 집계, 중복 삼각형 변환, 중복 카메라 좌표 계산을 줄였습니다. 기존 캐시 한도와 변경 감지는 유지합니다.
- CPU 라이브러리가 없으면 기존 NumPy/Numba 경로를 사용할 수 있습니다. 설치 패키지는 새 DLL을 포함합니다.

검증: CPU 회귀/직접 비교 테스트 95개 통과. C++ 라이브러리를 비활성화한 기존 경로도 통과했습니다. 실제 Maya에서 스킨 프레임 변경·Undo·크리즈·하드 엣지·인스턴스·부모 변환, 메모리/파일 전달, 전체/부분/재질 라인셋 전환을 검사했습니다. Merge Groups와 Render Elements의 직렬/동시 준비 결과도 일치했습니다.

실측 원본과 이미지: `evidence/render098/`. GitHub에는 게시하지 않은 로컬 검증본입니다. 설치 후 Maya를 다시 실행해야 새 네이티브 코드를 사용합니다.
